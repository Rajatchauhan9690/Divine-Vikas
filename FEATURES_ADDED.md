# Divine Vikas features

This document summarizes the customer, admin, payment, and integration capabilities currently implemented in the application. For setup instructions and configuration, see [README.md](./README.md).

## Storefront

- Responsive product catalogue with product details, search, category filtering, and cart.
- Customer registration, login, and authenticated profile and order pages.
- Support page with optional WhatsApp, email, and phone contact details.

## Customer profile and delivery addresses

- View and update customer name and phone number; email is read-only.
- Save up to three delivery addresses, edit or delete them, and choose a default.
- Validate profile and address data on the server.

## Product checkout and orders

- Choose a saved delivery address or enter an address during checkout.
- Cashfree online checkout; product prices, stock, and totals are determined by the server.
- Temporary inventory reservation for pending payment attempts. Successful, failed, and expired attempts are handled server-side.
- Email confirmation is sent to the customer's account email after successful order payment.
- Order history includes purchased items, total, payment and fulfilment status, delivery address snapshot, and status timeline.
- Change an eligible order's address before shipment; changes to a saved address do not alter an existing order's address snapshot.
- Cancel eligible orders and request product returns where the item's saved return policy permits.
- Product return policy is configurable as non-returnable or a 1–90 day return window and is recorded on each order item at purchase.

## Class sessions and bookings

- Browse upcoming sessions, inspect available seats, and make authenticated bookings.
- Reserve one or two seats in one Cashfree checkout.
- Seat holds last up to 20 minutes; seats are confirmed only after server-side Cashfree payment verification.
- Review active payment holds and confirmed class bookings.
- Admins can create and edit class sessions, set per-seat pricing, and delete an upcoming session only when it has no active holds or booked seats.
- Seats are generated by the server. Class seat reservation and confirmation use atomic database updates to prevent overlapping bookings and partial group reservations.
- Email confirmation is sent to the customer's account email after successful seat payment.

## Admin dashboard and fulfilment

- Admin-only dashboard overview and separate product, class, and order management views.
- Product create, edit, delete, image upload, and return-policy controls.
- Class session creation, editing, pricing, and eligible deletion.
- Update order status and customer-facing fulfilment notes; add courier and tracking details.
- Shiprocket courier discovery, shipment/label creation for eligible paid orders, and tracking webhook updates when configured.
- Review returns, mark received return items, and initiate eligible refunds through Cashfree.
- Cashfree payments cannot be manually marked paid through admin order updates.

## Payment lifecycle

- Cashfree payment-order creation happens on the server for both products and class seats.
- Provider credentials remain in server environment variables.
- Payment webhooks use raw-body HMAC signature validation; redirect returns are followed by provider-side status verification.
- Successful payments are protected against duplicate processing.
- Product inventory and class seats are temporarily reserved during checkout and released when eligible attempts or holds expire or fail.
- Cashfree refunds are initiated for eligible paid-order cancellations and accepted returns; refund status is tracked separately from order payment status.

## Security and reliability

- Short-lived access tokens and rotating refresh tokens in HttpOnly cookies, hashed refresh-token records, and session revocation.
- Bcrypt password hashing and customer/admin role-based access control.
- CSRF checks for cookie-backed authentication mutations, origin checks, Helmet, explicit CORS, and request-size limits.
- Authentication and API rate limiting, database-backed login lockout, and input validation.
- Customer resources are scoped to their owner; admin routes require the admin role.
- Atomic class seat holds prevent overlapping reservations and partial multi-seat holds.
- Automated tests cover authentication protections and concurrent class-seat booking.

## Optional configuration

- **Cloudinary:** product image uploads; existing `/uploads` images continue to be served.
- **Cashfree:** sandbox or production payment processing and optional payment/refund webhooks.
- **Shiprocket:** courier options, shipment creation, labels, and tracking webhook.
- **Support contact details:** configured on the client through `VITE_SUPPORT_WHATSAPP`, `VITE_SUPPORT_EMAIL`, and `VITE_SUPPORT_PHONE`.

## Integration limitations

- Live payment and provider workflows require valid merchant credentials and configuration; sandbox behavior depends on the provider's current test procedures.
- Shiprocket courier availability, shipment creation, and tracking depend on account configuration and provider events.
- Refund completion is controlled by Cashfree after the refund request is accepted. Monitor pending provider refunds.
- A late product payment received after its stock reservation expires may require refund follow-up if the inventory cannot be reserved again.
